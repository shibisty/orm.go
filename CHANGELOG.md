# Changelog

## Unreleased

## 0.1.1 — 2026-11-09

### Added
- `orm.ErrNotSupported`: a driver lacks a capability (transactions in ClickHouse).
- `orm.IDGenerator`: drivers of databases without auto-increment generate the id of a new
  record; `Repository.Create` asks them when the entity's id is zero.
- `schema`: table options `Blueprint.Option(key, value)` (ClickHouse: engine, order_by,
  partition_by, primary_key, ttl, settings), `Index.Using(kind)`, and the optional dialect
  extensions `CreateTableDialect` and `RenameTableDialect`.
- `drivertest.SQLWith(t, conn, drivertest.Options{NoTransactions, NoUnique})` for databases
  without those capabilities; the suite checks they fail cleanly instead. New check: an id
  set by the application is kept by `Create`.

### Changed
- `Repository.Create` inserts the id when the entity already has one (it was always left
  to auto-increment), and only overwrites it with the database's id when there is one.

### Tests
- A test keeps the core free of drivers: `orm` and its subpackages may import only the
  standard library and `orm` itself.

## 0.1.0 — 2026-10-09

### Changed
- The package is installed with gtr: `gtr.json` replaces `go.mod` (generated by gtr, not
  committed), and packages of the family are imported by their gtr names (`import "orm"`,
  `"orm/schema"`, `"orm-postgres"`, `"passport"`, …) instead of `github.com/shibisty/...`
  paths (ADR-0001, ADR-0002). Packages that plug into a core list it as a peer dependency.
  CI builds gtr-manager from source and runs `gtr install`.

### Breaking
- The Go package was renamed `core` → `orm`; the module path is `github.com/shibisty/orm.go`
  (was the placeholder `github.com/youruser/goorm/core`). `core.New` → `orm.New`, etc.
- `schema` moved into this repository: `github.com/shibisty/orm.go/schema`.
- `migrate` was removed: migrations are a separate package, `migration` (+ the `migration-orm` backend).
- `schema.Dialect.DropForeignKeySQL` returns `(string, error)`.
- Index and constraint names follow the Laravel convention and include the table name:
  `users_email_unique`, `posts_user_id_foreign` (were `email_unique`, `user_id_foreign`,
  which clashed across tables in Postgres and SQLite).

### Fixed
- `SELECT *` was scanned by position: with a different column order in the table or an extra
  column, data landed in the wrong fields or the query failed. Models now
  request the columns from their `db` tags.
- Postgres: `Repository.Create` inside a transaction did not get the id (RETURNING id ran via
  Exec). Added the `orm.InsertReturningID` extension.
- `Where(col, "IN", []T{...})` produced invalid SQL; it now expands to `($1, $2, …)`,
  and an empty slice becomes `1 = 0` (or `1 = 1` for `NOT IN`).
- `ORDER BY` inserted the column name unquoted (SQL injection via the column name).
- `SELECT *` with a JOIN: model columns are qualified with the table name (`"users"."id"`),
  otherwise `id` is ambiguous.
- `IN` with a scalar: `col IN ($1)` instead of the invalid `col IN $1`.
- `users.id` was quoted as a whole (`"users.id"`); it is now quoted part by part.
- INSERT/UPDATE columns and column renames in ALTER were emitted in random order.
- `FillStruct`: `int32`→float and unsigned numbers were not converted.
- Error messages prefixed with `goorm:`/`core:` → `orm:`.

### Added
- `KeyValueStore.Get` contract: a missing key returns `ErrNotFound`.
- `schema.AlterConstraintDialect` for databases without `ALTER ... ADD CONSTRAINT` (SQLite).
- `schema.IndexName`, `Blueprint.DropIndexCols`, `Blueprint.DropForeignCol`.
- `orm.QuoteIdent`.
- `drivertest`: a shared test suite for drivers (`SQL`, `NoSQL`).
- Tests: core 96%, schema 98%; CI.
